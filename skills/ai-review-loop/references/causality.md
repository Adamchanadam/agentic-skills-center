# 因果鏈核對模組（D 模式）

## 適用時機

材料有因果主張——「導致」「因為」「所以」「帶動」「歸因」「受惠於」「拖累」「成功是因為」——或策略、研究、投資結論依賴某個原因成立時讀。最常見的問題不是資料錯，而是**資料正確、因果對錯了**：兩件事同時發生被寫成一件引致另一件，結論看似有數字支持，其實站在錯的原因上。

本檔屬 D 模式「找盲點」的一部分。發現同樣寫位置、影響、證據、根因，並只用 SKILL.md 的三組標籤。涉及數字的因果主張先完成 `numbers.md` 四步；財務敘事的因果主張配合 `finance.md` 第 6 項「敘事與數字互相支持」——該項查敘事與數字方向是否一致，本檔查「為甚麼」是否成立，兩邊互相引用，不重複做。

## 核心原則

- 一條鏈的可信度由**最弱一節**決定，不由最強一節或節數決定。
- 「找到另一個解釋」不等於推翻原主張；替代解釋同樣要標籤，不可因為是審查者提出就當成事實。
- 因果判斷大多只能到 INFERRED；要求每節 CONFIRMED 並不現實，重點是寫明依據及怎樣推翻，讓用戶知道結論靠甚麼站住。
- 不用通用理論代替材料證據：「加息通常令股價跌」是一般知識，不是這間公司這次下跌的證據。

## 步驟

### 1. 畫出條鏈

把材料的因果主張逐節寫出：「因為 A → 所以 B → 所以 C」。材料常常跳步（由 A 直接到 C），要把中間隱藏的一節補出來，因為錯誤往往藏在被跳過的那節。每節寫清楚是甚麼時候發生、涉及誰或哪個指標。

### 2. 逐節找證據並標籤

每一節（每個箭嘴）分別問：材料內有甚麼證據證明 A 真的引致 B？按證據標 **CONFIRMED**（材料或實測證據直接支持）、**INFERRED**（有依據的推論，寫明依據及怎樣推翻）、**UNVERIFIED**（沒有證據）。

寫法：`A →〔CONFIRMED〕B →〔INFERRED：依據…；推翻條件…〕C`。整條鏈的標籤取最弱一節；最弱一節是 UNVERIFIED 時，依賴這條鏈的結論也不可寫成已證實。

### 3. 查常見因果錯誤

逐項對照，每項命中要引用材料位置：

| 錯誤 | 一句話 | 怎樣查 |
|---|---|---|
| **方向倒轉** | 其實是 B 引致 A | 問：哪個先發生？倒轉後是否同樣說得通？ |
| **第三因素** | 另有 C 同時影響 A 和 B，兩者只是同時出現 | 列出同期還有甚麼變化（市場、季節、政策、對手） |
| **時間先後不對** | 結果早於原因出現，或相隔太遠 | 把 A、B 的日期並排；B 若在 A 之前已開始變，鏈不成立 |
| **影響大小不合理** | A 的規模撐不起 B 的變化 | 粗略計一次：A 最多能貢獻多少？餘下由誰解釋？ |
| **只是相關** | 兩個數字同步，但沒有機制說明為何 | 問：中間靠甚麼傳導？說不出機制就只到 INFERRED |
| **巧合時間點當原因** | 「做了 A 之後 B 就變」便歸因於 A | 看 A 之前 B 的走勢；本來已在變就不是 A 引起 |
| **單一原因** | 把多因結果歸於一個原因，通常是自己做過的事 | 列出所有可能原因及各自份量，看 A 是否只佔一小部分 |
| **倖存者偏差／樣本選擇** | 只看成功或留下來的案例推因果 | 問：失敗、流失、沒回應的案例去了哪裏？ |
| **回歸均值** | 極端值之後自然回落，被當成措施有效 | 看干預前是否剛好處於歷史高位或低位 |

這些是最常見的九種；材料只要命中一種，對應那一節最高只能標 INFERRED，並要在「怎樣推翻」寫明。

### 4. 反事實

對每條鏈的關鍵一節問：「如果沒有 A，B 還會不會發生？」再補兩個：「有 A 但 B 沒發生的例子存在嗎？」「A 的大小變了，B 有沒有跟着變？」答不到就寫明是未知，不填。反事實是幫助判斷的問題，本身不是證據，答案要標 INFERRED 或 UNVERIFIED。

### 5. 寫入發現與測試案例

- **發現與根因：** 列出整條鏈及每節標籤，根因指向最弱一節，影響寫「哪個結論因此不能成立或要降級」。例如：「結論『加價令流失率升』最弱一節 UNVERIFIED，因此建議『回調價格』不能作為必要行動，只能列為待驗證假設。」
- **測試案例：** 結論依賴某個因果主張時，設必要案例「關鍵因果節點有證據」。寫法：編號、輸入（該條鏈及材料位置）、通過條件：結論的說法強度不超過最弱一節的標籤——寫成已證實（「證明」「主要原因」）的，該節須至少 INFERRED 並寫明依據及推翻條件；最弱一節是 UNVERIFIED 時，結論須改寫為「同期出現、份量待分拆」之類並列出要補的證據，否則 FAIL、必要。另可加參考案例「反事實已回答」及「九種常見錯誤已逐項對照」。
- **修根因：** 最小修改通常是改寫結論的可信度（把「因為 A 所以 B」改為「B 與 A 同期出現，是否由 A 引致仍待 X 證據」），或補上要查的證據清單，而不是推倒整份方案。

## 檢查清單

- [ ] 因果主張已全部找出並畫成鏈？跳步處已補回中間一節？
- [ ] 每節有標籤？整條鏈取最弱一節？
- [ ] 九種常見錯誤逐項對照，命中處引用材料位置？
- [ ] 反事實三問已問，答不到的寫未知？
- [ ] 替代解釋同樣標了籤，沒寫成事實？
- [ ] 鏈內的時效事實（政策、利率、市場數據）按 SKILL.md「時效資料」一節查證及附日期？
- [ ] 「關鍵因果節點有證據」已設為必要案例？
- [ ] 財務敘事的因果已與 `finance.md` 第 6 項對照，沒重複寫兩次？

## 常見錯誤（用本模組時）

- 把每條鏈都要求 CONFIRMED 才過——因果大多只能到 INFERRED，過嚴會令所有結論失效，用戶無法行動。
- 鏈畫得太長太細，把每句話都拆成因果——只畫結論真正依賴的一兩條。
- 提出替代解釋後就宣稱原主張錯了——替代解釋沒有證據時同樣是 UNVERIFIED。
- 用一般知識（教科書式的「通常如此」）當作這次個案的證據。
- 只查因果不查數字——A 對 B 的影響大小要靠 `numbers.md` 的重算及敏感度支撐。
- 發現寫成「因果有問題」而不指明哪一節、甚麼標籤、推翻條件是甚麼。

## 簡短測試例子

**例一（示意）**
材料：「本季股價下跌，主因是央行加息。」
畫鏈：加息 →〔?〕資金成本上升 →〔?〕估值下調 →〔?〕股價跌。
逐節：加息事件 CONFIRMED（有日期，屬時效資料，需附來源）；加息→估值下調 INFERRED（一般機制，但同期公司下調盈利指引，屬第三因素）；估值下調→本公司股價跌 UNVERIFIED（同業同樣受加息影響但跌幅較小，加息撐不起本公司較大的跌幅，屬影響大小不合理）。最弱一節是 UNVERIFIED。
反事實：如果沒有加息，盈利指引下調後股價會否照跌？材料沒有回答。
發現：「主因是加息」最高只能 INFERRED，更可能的解釋是盈利預期下調，加息只是同時發生。建議改寫為「股價下跌期間同時出現加息及盈利指引下調，兩者份量未能分拆」，並設必要案例 T：「結論說法強度不超過最弱一節」——原文寫「主因」而最弱一節是 UNVERIFIED，現為 FAIL；改寫為「份量未能分拆」並列出要補的證據後可以通過。

**例二（示意）**
材料：「推廣活動帶動銷量升 25%。」
查：活動前三個月銷量是否已在上升（巧合時間點）？活動期是否旺季（第三因素）？25% 之中活動渠道貢獻多少（影響大小，用 `numbers.md` 重算）？答不到的標 UNVERIFIED，結論改為「銷量升 25% 與活動同期，活動貢獻份量待分拆」。
