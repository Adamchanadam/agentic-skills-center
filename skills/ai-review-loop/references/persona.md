# Persona 模組：建立及使用模擬用戶（U 模式）

## 適用時機

用戶要模擬用戶、做 U 模式、要你「扮某類人睇一次」，或用戶只給幾個要點（例如「三四十歲、為子女揀小學的家長」）要你補完角色時讀。

## 核心原則

- 角色是設計出來的假設，不代表真實用戶；模擬反應不是用戶數據，發現一律標 **SIMULATED**。
- 角色數目由未覆蓋的風險決定，不是愈多愈好。只有一個方案時不必硬造對照。
- 未知不得虛構：事實卡有「明確未知」一欄，就是用來寫「不知道」的。
- 避免刻板印象：差異要來自處境（收入、時間、資訊渠道、決策壓力），不是來自身份標籤本身。

## 步驟

### 1. 由要點提議角色（用戶確認後才模擬）

按用戶給的要點，提議 2–4 個覆蓋**不同風險**的角色，每個一句話講清楚「這個角色會暴露甚麼問題」。例如為子女揀小學的家長：

- 雙職家庭、收入中等、時間最緊——會暴露流程太長、資料太多的問題。
- 新來港或非本地語言家庭——會暴露用詞、假設背景知識的問題。
- 高度關注學業成績、資訊充足——會暴露內容不夠深、數據不透明的問題。
- 有特殊教育需要子女的家長——會暴露例外情況無路可走的問題。

列出後**請用戶確認、刪減或替換**，確認前不開始模擬。用戶已明確給定角色則直接用，不重提。

### 2. 補完背景（每項標來源）

每個角色補完：家庭狀況、收入或預算、時間限制、資訊渠道、決策考慮（最在意甚麼、最怕甚麼）、該情境所需的專業知識（例如小學派位機制、報名時間表）。

每項背景標明來源，三選一：
- **用戶提供**
- **AI 補充（附依據）**——背景屬時效類別（政策、收費、時間表、人事等，清單見 SKILL.md「時效資料」一節）時一定要查最新並註明來源及日期，不靠自覺判斷；查不到則標「一般知識，UNVERIFIED（未查證）」，並寫明影響哪些模擬結果。
- **假設**——純粹為了模擬而設，用戶可改。

### 3. 寫事實卡

每個角色一張，四欄齊全：

```
角色：〔名稱／一句話定位〕
已知：〔每項附來源：用戶提供／AI 補充（來源、日期）／假設〕
明確未知：〔不知道的就寫這裏，不要補〕
目標／限制：〔想完成甚麼；時間、金錢、能力限制〕
表達習慣：〔用甚麼語言、看不看長文、信甚麼渠道〕
```

事實卡附在報告的比較紀錄之後。

### 4. 模擬

每個角色執行測試案例（某類用戶完成某項任務），逐步記錄：在哪一步卡住、誤解了甚麼、為何放棄或繼續。每項發現寫位置、影響、證據（引用材料原文）、根因，標 SIMULATED。

角色之間的差異要解釋：同一句話為何 A 看得明 B 看不明——答案應落在事實卡的某一欄。

## 檢查清單

- [ ] 角色是否覆蓋不同風險，而不是同一類人換個名字？
- [ ] 每項背景是否標了來源？「AI 補充」有沒有依據及日期？
- [ ] 「明確未知」是否有內容？全部填滿通常代表有虛構。
- [ ] 用戶是否確認了角色才開始模擬？
- [ ] 發現是否全部標 SIMULATED，沒有混入 CONFIRMED？
- [ ] 有沒有刻板印象（例如以年齡或族群直接推斷能力或態度）？
- [ ] 報告會交給他人時，事實卡有沒有不必要的個人資料（真實客戶姓名、聯絡方式）？

## 常見錯誤

- 用戶給了三個要點，AI 補成一篇人物小傳，沒標哪些是假設。
- 角色「反應」寫成真人口吻的長篇獨白，掩蓋了其實沒有證據。
- 把模擬結果寫成「用戶會覺得」——應寫「角色 A（SIMULATED）在第 3 步卡住，因為……」。
- 四個角色全部中產、全部資訊充足，看似覆蓋廣，其實只測了一種風險。
- 為了令角色「真實」而虛構具體收入數字或家庭故事，卻標成「AI 補充」。

## 簡短測試例子

輸入：「用家長角度睇吓呢份小一入學簡介，家長大概三四十歲。」
預期：先提議 3 個覆蓋不同風險的家長角色，請用戶確認；確認後每個角色一張事實卡，派位機制、報名時間表等屬時效資料，必須標「AI 補充（來源、日期）」或「一般知識，UNVERIFIED」；模擬後每項發現標 SIMULATED，指出卡在簡介的哪一段。
