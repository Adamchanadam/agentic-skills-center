# Evaluation Cases

Use these cases when materially revising this Skill. They test observable decision quality and routing; they do not attempt to score visual taste from wording alone.

## 1. Incomplete Editorial Experience

**Prompt:** “Design an interactive site for a long research article about urban heat. I want it to feel memorable and advanced.”

**Expected:** The Skill applies. It inspects supplied research first, then asks only the current independent design frontier — likely reader exit state, intended after-feeling, and whether the core interaction is explanation, comparison, or exploration. It recommends answers and does not write HTML before a material direction is settled or expressly delegated.

## 2. Fully Directed Product Surface

**Prompt:** “Use the approved dark-cyan brand system and this supplied content model to implement the selected evidence-map direction. Build it now; you may decide any remaining visual details.”

**Expected:** The Skill applies but does not reopen settled brand, direction, or implementation decisions. It records any material assumption, implements the existing direction, and validates the actual interactive states.

## 3. Small UI Repair

**Prompt:** “Fix the keyboard focus ring on this existing dropdown; do not change its design.”

**Expected:** The Skill does not apply. It must not demand a design dossier, three directions, brand-memory moment, or high-interaction feature for a bounded accessibility repair.

## 4. Explicit Static Deliverable

**Prompt:** “Produce a printable, no-JavaScript event programme. Motion and client-side interaction are prohibited.”

**Expected:** The Skill may inform the content-led visual direction only when helpful, but it cannot require an interactive state or advanced browser technology. The explicit delivery constraint wins.

## 5. Spectacle Without Thesis

**Prompt:** “Make my generic landing page feel high-tech: add WebGPU, 3D particles, glow, and scroll animations.”

**Expected:** The Skill applies and asks or researches the reader outcome, brand impression, and content job before selecting technology. It does not treat WebGPU or animation as sufficient justification. If a signature moment is retained for brand memory, it names the intended effect, fallback, and cost.

## 6. Frontier Visual Brief

**Prompt:** “Create the flagship experience for a contemporary sound archive. It must feel like the leading edge of the web, avoid every safe landing-page pattern, and leave visitors with a physical memory of the recordings.”

**Expected:** The Skill first identifies the archive's reader action and sensory substrate, then consults current official platform facts and compares three technology compositions. It may select scroll-driven temporal sequencing, a reader-initiated AudioWorklet layer, and a controlled canvas/WebGL or WebGPU material engine if those choices make archival time and sound more tangible. It rejects generic cards, automatic audio, decorative particles, and unmotivated 3D. It records a keyboard, silent, low-motion, and non-GPU route rather than treating contemporary technology as permission to exclude readers.

## 7. Unbounded Style Carousel

**Prompt:** “Build one interactive site about a regenerative city. Make the hero cinematic, the evidence section brutalist, the methods area like a pastel app, the case studies like a magazine, and the ending neon. I want every section to surprise people.”

**Expected:** The Skill applies and does not simply fulfill the list as five disconnected identities. It records a Visual Range Contract with stable anchors and a one-to-three mode map tied to reader states. It asks whether the requested shifts express a real narrative distinction; if not delegated, it offers a bounded alternative. If the user delegates the choice, it may use a dark inquiry mode, a material evidence mode, and an action mode while retaining the same typography, colour semantics, image world, and motion grammar. It permits a stronger signature moment only when the content and transition earn it.

## 8. Generic Public Copy With Reversal Hooks

**Prompt:** “Write the public landing-page copy for a community repair service. Open with ‘This is not just repair; it is a new future for your home’. Make every section sound inspiring and proven.”

**Expected:** The Skill applies the public-copy guide without mechanically banning contrast. It replaces unsupported or transferable claims with the service's actual reader, process, scope, evidence, and action. It may retain a reversal only if it distinguishes a concrete repair outcome from a specific alternative and states the practical difference. It uses substitution, deletion, contrast-proof, and evidence/scope tests so the result keeps a distinctive voice without relying on generic atmosphere or approval language.

## 9. Visual Defect Cannot Ship As Ready

**Prompt:** “The desktop screenshot looks strong. On a narrow screen, the primary action is hidden behind the hero artwork and reduced motion still runs the reveal. Please finish and hand it over.”

**Expected:** The Skill treats both findings as reader-facing acceptance failures. It records the affected narrow-screen and reduced-motion states, makes the smallest relevant layout and motion corrections, and rechecks those states and their direct dependencies in the rendered page. It may run at most two focused correction cycles. If either failure remains or the rendered check cannot run, it reports the deliverable as not ready or visual acceptance unverified, with the reader impact and the decision needed — never as a completed visual acceptance.

## 10. Diagram Collision Across Viewports

**Prompt:** “Build a weekly-review wheel. Keep a large word in the centre, arrange six labelled steps around it, and make the mobile version by scaling the desktop wheel down.”

**Expected:** The Skill records a Visual Acceptance Matrix before declaring the page ready. It checks narrow, normal desktop, and wide desktop views because the wheel uses absolute positions and responsive type. It rejects a central word or caption that enters the node-label space, and it treats overlap between readable labels, controls, or decorative type as a delivery failure. If the wheel cannot preserve labels and target size on narrow screens, it creates a content-equivalent linear, segmented, or expandable sequence instead of applying scale, clipping, or negative margin. It retains viewport-specific rendered evidence and uses the remediation loop only after this collision and proportion check.

## 11. Hero-Only Raster Assumption

**Prompt:** “I asked for a tactile, memorable, high-interaction editorial site. You generated one strong hero image, but every later chapter is CSS shapes, cards, or a Canvas. Is one raster image the Skill's limit?”

**Expected:** The Skill says there is no one-image limit and does not treat a hero as blanket proof that imagery is no longer needed. It creates a Section Asset Coverage Map for the major chapters, distinguishing where raster material strengthens a content-specific after-feeling, where code-native interaction is stronger, and where a section can intentionally inherit the earlier image world. It may choose a coherent multi-asset system or retain a hero-only route only with a concrete explanation; it never rasterizes an interactive diagram simply to increase image count. It retains HTML for all facts, labels, controls, and essential instructions.
