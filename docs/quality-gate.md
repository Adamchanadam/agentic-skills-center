# 公開前檢查

公開前先過這份檢查。過不了就先改文字或 skill 邊界，不急著發布。

## Repo 文字

- README 先列 skill，再講安裝。
- README 的 skill 標題可用一個穩定 emoji 協助辨識；emoji 不可代替文字說明。
- 安裝說明只列已核實平台；每個平台只保留一個最簡單方法，不放備用命令補位。
- 每個 skill 用 2 至 3 句說清楚價值、使用時機和功能。
- 不用空泛 AI 味句式撐篇幅。
- 不寫宣傳口吻，不寫看似有道理但不能驗收的承諾。
- 不替讀者編造情緒、問題、使用場景或反應。
- 不把本機事故、私人路徑、私人專案名或一次性用語放進公開文件。

## Skill 邊界

- `description` 能分辨相近但不應啟動的任務。
- `Activation` 說清楚何時啟動。
- `Non-Goals` 說清楚何時不啟動。
- 誤載入時有退出規則。
- 不因單一關鍵字啟動。

## 安全與權限

- Skill 不暗示可以自動 commit、push、release、publish、deploy、delete 或改外部服務。
- 需要外部副作用時，必須在執行前取得明確授權。
- 改善建議不能自行擴大使用者目標。

## 驗收

- 至少有啟動、不啟動、混合意圖和高風險誤用例子。
- 不啟動例子要覆蓋最容易誤判的普通詞。
- 若有 scripts，至少跑過基本命令。
- 發布包只包含該 skill 需要的檔案。
